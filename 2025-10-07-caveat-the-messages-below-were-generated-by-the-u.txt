● E2E Test Refactoring Plan

  Based on the refactoring plan document, here's a clear execution plan:

  Overview

  Migrate from global fixtures to a factory pattern with scoped builders to achieve test isolation, improve readability, and enable concurrent test execution.

  Implementation Plan

  Phase 1: Setup Infrastructure (Week 1)

  1.1 Install Dependencies
  - Add @faker-js/faker for realistic test data generation

  1.2 Create Factory Files (test/factories/)
  - customer.factory.ts - Generate customer DTOs with faker
  - product.factory.ts - Generate product DTOs with faker
  - order.factory.ts - Generate order DTOs with customerId/productIds

  1.3 Create Helper Utilities (test/helpers/)
  - test-data-builder.ts - CRUD operations to create/persist test entities via API
  - test-cleanup.ts - Cleanup utilities for test teardown

  Phase 2: Create Specialized Builders (Week 1-2)

  2.1 Build Domain-Specific Test Builders
  - LoyaltyTestBuilder - Create customers in specific loyalty tiers (Bronze/Silver/Gold/Platinum)
  - OrderTestBuilder - Create orders in specific states (PENDING/PREPARING/READY/DELIVERED/CANCELLED)
  - CustomerTestBuilder - Create customers with various relationship states

  Key Builder Methods:
  - createBronzeTierCustomer() - 0 orders, $0 spent
  - createGoldTierCustomer() - 7 orders worth $300+
  - createCustomerNearDiscount() - 3 orders (1 away from 5% threshold)

  Phase 3: Refactor Tests Module-by-Module (Week 2-4)

  Migration Order (simple → complex):

  1. app.e2e-spec.ts - Health checks (minimal fixtures)
  2. product.e2e-spec.ts - Product CRUD (12 tests, no dependencies)
  3. customer.e2e-spec.ts - Customer CRUD (20 tests, some order relations)
  4. order.e2e-spec.ts - Order management (complex, needs customers + products)
  5. loyalty.e2e-spec.ts - Loyalty logic (40+ tests, most complex business rules)

  Per-File Strategy:
  - Keep old test file intact initially
  - Create new test with factory pattern
  - Verify both pass
  - Replace old test
  - Ensure test count remains 102 total

  Phase 4: Remove Global Fixtures (Week 4)

  4.1 Verification
  - Run full test suite - verify 102 tests passing
  - Check test coverage remains at business logic coverage level
  - Verify no behavioral regressions

  4.2 Cleanup
  - Delete test/fixtures/global-fixtures.ts
  - Remove fixture loading from test setup
  - Remove helper methods: getDeletableProducts(), getUpdateTestCustomers(), etc.
  - Update test:e2e scripts if needed

  Success Criteria

  Metrics Targets

  - Test Independence: 100% (currently ~30%)
  - Test Readability: +60% (no magic indices)
  - Maintenance Time: -40% (self-contained tests)
  - Test Count: Exactly 102 tests (same coverage)
  - Concurrent Execution: Safe (currently impossible)

  Quality Checks

  - ✅ Each test understandable in isolation
  - ✅ No test order dependencies
  - ✅ No shared mutable state
  - ✅ Clear semantic test data
  - ✅ Easy to add new test cases

  Migration Example

  Before:
  it('should apply 10% discount', async () => {
    const customer = fixtures.getCustomers()[2]; // Who is customer 2? 🤷
    // ... creates orders, mutates shared state
  });

  After:
  it('should apply 10% discount for 6-10 orders', async () => {
    const builder = new LoyaltyTestBuilder(app);
    const customer = await builder.createCustomerWithOrders(6);

    const discount = await loyaltyService.calculateDiscount(customer.id);
    expect(discount).toBe(10);
  });

  Risk Mitigation

  Parallel Development:
  - Keep global fixtures working during migration
  - Migrate test-by-test, not file-by-file wholesale replacement
  - Tag commit before fixture deletion for rollback

  Verification:
  - Run both old and new tests in parallel during transition
  - Count tests using own data vs shared fixtures to track progress
  - Verify business logic coverage remains constant

  Timeline Estimate

  - Week 1: Infrastructure + Builders
  - Week 2-3: Migrate 3-4 test files
  - Week 4: Final migration + cleanup

  Total: 4 weeks for complete migration with verification
