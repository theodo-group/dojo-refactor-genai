> Your approach doesn't prevent other similar issues to arise, how could we prevent it ? 

⏺ You're absolutely right - my approach just fixes the symptom, not the root cause. Here's how to prevent this class of issues systematically:

  Root Problem

  The loyalty service silently transforms data (totalAmount) during order creation, making it invisible and untestable.

  ---
  Preventive Solution: Make transformations explicit in the data model

  Change the Order entity to track:

  - originalAmount - what the customer was quoted
  - discountAmount - discount applied (if any)
  - finalAmount - what they actually pay

  @Entity('orders')
  export class Order {
    @Column('decimal', { precision: 10, scale: 2 })
    originalAmount: number;

    @Column('decimal', { precision: 10, scale: 2, default: 0 })
    discountAmount: number;

    @Column('decimal', { precision: 10, scale: 2 })
    finalAmount: number;

    // ... rest
  }

  Why this prevents future issues:

  1. Transparency: Any discount/transformation is visible in the response
  2. Testability: Tests can assert on all three values independently
  3. Audit trail: You can see exactly what discount was applied and why
  4. Self-documenting: The schema itself tells you discounts exist
  5. Future-proof: New transformations (taxes, fees, promos) follow the same pattern

  Alternative: Calculate expected values in fixtures

  Add a method to fixtures that returns the "expected" final amount after all business logic:

  getExpectedOrderAmount(customerId: string, originalAmount: number): number {
    // Apply same logic as loyalty service
    const customer = this.customers.find(c => c.id === customerId);
    const orderCount = this.orders.filter(o => o.customer.id === customerId).length;
    return orderCount > 3 ? originalAmount * 0.9 : originalAmount;
  }

  But this duplicates logic - not ideal.

  ---
  Recommended: Data Model Change (Option 1)

  This is the only truly preventive solution because:
  - ✅ Makes side effects impossible to hide
  - ✅ Forces explicit handling of transformations
  - ✅ Makes tests naturally correct
  - ✅ Provides business value (discount visibility)
  - ✅ Scales to future features (taxes, tips, promotions)

  Trade-off: Requires migration + minor refactoring, but prevents entire categories of bugs.
