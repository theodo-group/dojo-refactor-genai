  The Issue:
  - All tests share the same fixture data loaded once in beforeAll()
  - Tests depend on specific fixture data (e.g., finding orders with status READY or DELIVERED)
  - Some tests mutate data (status updates, deletes), which can break subsequent tests
  - Tests are tightly coupled to the exact fixture structure

  The Plan:

  1. Refactor GlobalFixtures to use factory methods instead of bulk loading:
    - Add createCustomer(overrides?) method for creating individual customers
    - Add createProduct(overrides?) method for creating individual products
    - Add createOrder(customerId, productIds, overrides?) method for creating individual orders
    - Keep clear() but remove the bulk load() approach
  2. Add a fixture builder pattern for easier test data creation:
    - Create CustomerBuilder, ProductBuilder, OrderBuilder classes
    - Allows fluent API: builder.withName('John').withEmail('john@test.com').build()
    - Makes test data creation more readable and flexible
  3. Refactor the test file:
    - Remove fixtures.load() from beforeAll()
    - Add beforeEach() to clear data before each test
    - Each test creates only the data it needs using factory methods
    - Tests become independent and self-documenting
  4. Alternative approach for better isolation (optional enhancement):
    - Use database transactions with rollback in afterEach()
    - Or use separate test databases per test suite
    - Ensures complete data isolation between tests
  5. Update test assertions to not depend on hardcoded fixture counts:
    - Instead of expect(res.body.length).toBe(fixtures.getOrders().length)
    - Use more specific assertions based on what the test actually created

  This will make tests:
  - Independent: Each test creates its own data
  - Readable: Test setup documents what data is needed
  - Maintainable: Changes to fixtures don't break unrelated tests
  - Fast: Only create what's needed per test
